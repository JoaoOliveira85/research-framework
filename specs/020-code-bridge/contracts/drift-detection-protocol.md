# Schema Drift Detection Protocol (D8)

When a vault author sets `manually_edited: true` on their
`<vault>/_pipeline/sources/<module>/facts-schema.json`, the framework
stops auto-regenerating the schema. **But** the underlying
`research.spec.md` can still change. This protocol specifies how
the framework detects, reports, and resolves the resulting drift.

## State machine

```
                      ┌─────────────────────────────────┐
                      │ Schema in steady state          │
                      │ (manually_edited: true,         │
                      │ .schema-gen-hash matches spec)  │
                      └─────────────────────────────────┘
                                    │
                          spec.md changes
                                    │
                                    ▼
                      ┌─────────────────────────────────┐
                      │ DRIFT DETECTED                   │
                      │ (next cycle start; .hash !=     │
                      │ sha256(current spec.md))        │
                      └─────────────────────────────────┘
                                    │
                         framework actions:
                                    │
                                    ▼
                      ┌─────────────────────────────────┐
                      │ 1. Run schema-gen → sidecar      │
                      │    facts-schema.regenerated.json │
                      │ 2. Diff manual vs regenerated   │
                      │    → facts-schema.drift.md       │
                      │ 3. Raise StaleManualSchemaError │
                      │ 4. Cycle ABORTS (fail-closed)   │
                      └─────────────────────────────────┘
                                    │
                            user picks one of:
                                    │
        ┌───────────────────────────┼───────────────────────────┐
        │                           │                           │
        ▼                           ▼                           ▼
  (a) acknowledge          (b) un-manual            (c) --force-stale-schema
  (merge & bump hash)      (remove flag)            (proceed, one-time)
```

## File layout during drift

```
<vault>/_pipeline/sources/<module>/
├── facts-schema.json                    # manual schema (manually_edited: true)
├── facts-schema.regenerated.json        # fresh schema-gen output
├── facts-schema.drift.md                # human-readable diff + resolution paths
└── .schema-gen-hash                     # sha256 of spec.md AT LAST RESOLVED state
```

Once the user resolves (any path), the sidecars are deleted:

```
<vault>/_pipeline/sources/<module>/
├── facts-schema.json                    # (manual, possibly updated)
└── .schema-gen-hash                     # sha256 of CURRENT spec.md
```

## `facts-schema.drift.md` format

Strictly markdown; intended for human reading. Generated by the
framework via a deterministic diff algorithm (NOT an LLM call).

```markdown
# Schema Drift Detected: <module>

**Manual schema** at: `_pipeline/sources/<module>/facts-schema.json`
**Last resolved** spec_hash: `<old_hash>` (recorded <date>)
**Current** spec_hash: `<new_hash>`

The `research.spec.md` file has changed since you last edited or
acknowledged this schema. A fresh regeneration sits next to your
manual schema as `facts-schema.regenerated.json`.

## Added buckets

Top-level properties present in the regenerated schema but missing
from your manual schema:

- `<name>` (`<type-summary>`) — <description from regenerated>

## Removed buckets

Top-level properties present in your manual schema but NOT in the
regenerated schema:

- `<name>` (`<type-summary>`)

## Changed bucket shapes

Top-level properties present in both but with different types or
structures:

- `<name>`:
  - manual: `<type-summary>`
  - regenerated: `<type-summary>`

## Resolution paths

Pick ONE of:

### (a) Merge the regenerated schema

1. Diff:
   `diff facts-schema.json facts-schema.regenerated.json`
2. Manually edit `facts-schema.json` to incorporate the changes
   you want.
3. Acknowledge drift:
   ```bash
   research-framework schema --acknowledge-drift <module>
   ```
   This bumps `.schema-gen-hash` to the current spec hash and
   removes the sidecar files.

### (b) Stop being manual

Remove `"manually_edited": true` from `facts-schema.json`. The next
cycle will auto-regenerate authoritatively.

### (c) Proceed with stale schema (one-time)

```bash
research-framework generate --force-stale-schema
```

The cycle runs with the manual schema as-is. Drift sidecars remain.
This counts as an explicit waiver; the next cycle will detect the
same drift and halt again unless you resolve via (a) or (b).
```

## Diff algorithm

Deterministic structural diff. NOT an LLM call.

1. Load both schemas as JSON.
2. For each top-level property in either schema's `properties`:
   - In regenerated only \u2192 "Added".
   - In manual only \u2192 "Removed".
   - In both \u2192 compare via `json.dumps(sort_keys=True)`. Different \u2192
     "Changed bucket shapes".
3. Type summary: render the schema fragment as a short string
   (e.g. `list[str]`, `list[{name, kind}]`, `object`, etc.) using
   a small recursive renderer (~50 LOC).

## CLI surface

| Command | Effect |
|---------|--------|
| `research-framework generate` | Fail-closed on drift; pointer to drift.md. |
| `research-framework generate --force-stale-schema` | One-time bypass; sidecars stay; next cycle still halts unless resolved. |
| `research-framework schema --acknowledge-drift <module>` | Bump hash to current spec; remove sidecars; assumes user merged. |
| `research-framework schema --regenerate <module>` | Force schema-gen regardless of `manually_edited`; overwrites manual schema; bump hash. |

## Test fixtures

`tests/source_bridge/test_schema_drift.py` covers:

- **`test_no_drift_no_action`** \u2014 `.schema-gen-hash` matches; no
  sidecars produced.
- **`test_drift_detection_writes_sidecars`** \u2014 spec.md changes;
  framework writes both sidecar files.
- **`test_drift_fails_cycle_closed`** \u2014 drift detected; cycle aborts
  with `StaleManualSchemaError`; non-zero exit code; error message
  cites drift.md path.
- **`test_force_stale_schema_proceeds`** \u2014 `--force-stale-schema`
  flag set; cycle continues; sidecars remain on disk.
- **`test_acknowledge_drift_resolves`** \u2014 `schema --acknowledge-drift`
  bumps hash; sidecars deleted; subsequent cycle runs cleanly.

## Implementation hint

Drift detection lives in `schema_gen.py::detect_drift()`. Called at
pipeline start before any source extraction. Raises
`StaleManualSchemaError` (extends `RuntimeError`) which
`cycle_runner` catches at the top level and converts to a clean
fail-closed cycle abort.
