# Contract: `./vault regenerate-shim` (FR-014)

**Phase**: 1 only  
**Status**: Draft (plan artifact)  
**Implements**: FR-014, FR-001, FR-002 (optional `--json` status)  
**Spec reference**: `specs/023-flow-separation/spec.md` → FR-014, archaeology F2

## Purpose

Re-render the vault's `./vault` bash shim from `templates/vault-script.sh.j2` using:
- `vault_dir` = resolved absolute path to the vault
- `spec` = parsed `research.spec.md` (name + metadata for template)

Fixes broken shims with stale macOS temp `VAULT_DIR` and pre-0.2.33 `research_vault.cli` module paths.

## Invocation

```bash
./vault regenerate-shim [options]
# Framework CLI:
python -m research_framework.cli regenerate-shim --vault <path> [options]
```

### Options

| Flag | Description |
|------|-------------|
| `--dry-run` | Print intended `VAULT_DIR`, template version, customization assessment; do not write |
| `--force` | Overwrite even when heuristic marks shim as customized |
| `--json` | Emit result object to stdout (exit metadata + paths) |

## Render inputs

| Input | Path | Required |
|-------|------|----------|
| Template | `templates/vault-script.sh.j2` (bundled asset) | yes |
| Spec | `<vault>/research.spec.md` | yes |
| Settings | `<vault>/settings.yaml` | no (template uses spec primarily; settings for future hooks) |

Render context (matches `generator/scaffold._write_vault_script`):

```python
{"vault_dir": str(vault.resolve()), "spec": spec_config}
```

## Write behaviour

1. Render template to string.
2. Write via `atomic_write.write_text(<vault>/vault, content, mode=0o755)`.
3. Update `_pipeline/shim-fingerprint.json` (see `data-model.md` §2).

## Customization detection

| Condition | Classification |
|-----------|----------------|
| File missing | `stock` — create without prompt |
| Sentinel `Generated by research-framework` present AND `_pipeline/shim-fingerprint.json` exists AND sha256 matches recorded fingerprint | `stock` — safe overwrite |
| Sentinel present AND `_pipeline/shim-fingerprint.json` MISSING (first regenerate-shim run on this vault) | `unverified` — treat as customized; require `--force` |
| Sentinel missing OR sha256 != fingerprint | `customized` — warn; require `--force` unless `--dry-run` |

**Why the `unverified` row exists**: vaults generated before spec 023 ships have no `shim-fingerprint.json` on disk. We cannot distinguish "the operator never touched the shim" from "the operator edited the shim during the broken `install.sh` era" without a recorded baseline. Failing closed (require `--force` on the first regenerate-shim run per vault) protects against silent loss of operator edits. After the first successful `--force` regenerate, the fingerprint is recorded and subsequent runs use the regular `stock` / `customized` split. This aligns with `research.md` §3, which states `stock` requires BOTH sentinel present AND hash match — `unverified` covers the bootstrap case explicitly.

**Non-interactive default**: If `customized` OR `unverified` and not `--force`, exit **2** with stderr explaining use of `--force`. No TTY prompt (headless-safe). Optional future: `--interactive` prompt — out of Phase 1.

## Relationship to `install.sh`

| Path | Behaviour |
|------|-----------|
| `./vault update` | Still runs `install.sh` from framework archive (may not pass `VAULT_DIR` correctly until spec 027) |
| `./vault regenerate-shim` | **Does not** invoke `install.sh`; only rewrites `vault` shim |
| Initial `generate` | `_write_vault_script` skips existing `vault` — regenerate-shim is the repair path |

Phase 1 also changes `dist-templates/scaffold-manifest.json`: `vault` entry → `is_user_owned_after_first_write: false` so update apply can overwrite shim when operator chooses update path post-027.

## Stdout / stderr

### Human mode

```
[regenerate-shim] vault=/Users/.../feeds-vault
[regenerate-shim] wrote vault (755), sha256=abc123...
```

### `--json` mode

```json
{
  "vault": "/Users/me/Documents/feeds-vault",
  "path": "vault",
  "sha256": "...",
  "classification": "stock",
  "overwritten": true,
  "framework_version": "0.3.2"
}
```

## Exit codes

| Code | Meaning |
|------|---------|
| 0 | Shim written (or `--dry-run` plan printed) |
| 1 | Reserved (unused Phase 1) |
| 2 | Missing spec, template error, customized without `--force`, atomic write failure |

## Idempotency

**Required**: Two consecutive runs with unchanged `research.spec.md`, `settings.yaml`, and template version produce **byte-identical** `vault` file.

Canonical path string in `vault_dir` must be stable (`Path.resolve()` on macOS/Linux).

## `vault-script.sh.j2` changes

Add case arm and help line:

```bash
  regenerate-shim)
    exec "${RV}" regenerate-shim --vault "${VAULT_DIR}" "$@"
    ;;
  refresh-sources)
    exec "${RV}" refresh-sources --vault "${VAULT_DIR}" "$@"
    ;;
```
