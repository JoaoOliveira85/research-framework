# Research: Spec 023 Flow Separation — Phase 1

**Date**: 2026-05-26  
**Scope**: US1 (partial) + FR-013, FR-014, FR-015, FR-018 only

## 1. Legacy collector invocation strategy

**Decision**: Spawn each collector as a **subprocess** using the vault venv Python (`{vault}/.venv/bin/python {vault}/scripts/collect_*.py`), with `cwd={vault}`, inherited environment, and a per-collector timeout from `settings.yaml` (default 600s).

**Rationale**:
- Collectors are standalone scripts with `if __name__ == "__main__"` blocks, argparse, and vault-relative paths — `runpy.run_path` would share process state and complicate signal/timeout handling.
- Subprocess matches how operators already run collectors manually and how `./vault health` invokes `scripts/vault_health.py`.
- Isolates collector crashes (exit 2) from framework CLI (exit 2 only on orchestration failure).

**Alternatives considered**:
- **`runpy` / importlib**: Rejected — collectors may mutate `sys.path`, assume fresh interpreter, or depend on `__file__` location.
- **`exec` via shell**: Rejected — escaping and cross-platform fragility; violates Principle IV style (prefer explicit Python subprocess list).

## 2. `refresh-sources` collector discovery

**Decision**: **Two-tier discovery**:
1. **Default**: Glob `scripts/collect_*.py` AND any additional legacy basenames declared in the framework allowlist (see below), sorted lexicographically together. Skip files that are not readable as Python files; do NOT filter on the executable bit (collectors are invoked via `python <script>.py` so the executable bit is irrelevant and many vault-local scripts ship non-executable by default).
2. **Optional override**: `settings.yaml` → `refresh_sources.collectors: [<basename>, ...]` (e.g. `collect_youtube.py`, `reddit_rss.py`) restricts order and membership; unknown names → stderr warning, exit 2 if none runnable.

**Legacy basename allowlist** (Phase 1, frozen list \u2014 ADR-0009 bridge): `reddit_rss.py`. The current feeds-vault uses `reddit_rss.py` as its Reddit collector (predates the `collect_*` naming convention). The allowlist is documented in the `refresh-sources` CLI contract and may grow as additional pre-`collect_*` scripts are identified during the revival sprint. Files matching the allowlist are discovered alongside `collect_*.py` and ordered lexicographically in the merged list. When spec 020 modules supersede collectors, the allowlist will be retired in lockstep.

Do **not** require a new top-level `[refresh_sources]` block in `research.spec.md` for Phase 1.

**Rationale**:
- Matches archaeology F6 (feeds-vault has `collect_youtube.py`, `collect_oreilly.py`, `reddit_rss.py` under `scripts/`; only the first two follow `collect_*`).
- ADR-0009 preserves legacy collector filenames as the stable bridge until spec 020 modules ship.
- Explicit override supports partial runs (YouTube-only) without editing the glob heuristic.
- Removing the executable-bit filter avoids silently skipping valid collectors that ship with mode `0644`.

**Alternatives considered**:
- **`scripts/sources.yaml` routing only**: Rejected for Phase 1 — enumeration belongs to 020 module manifests; refresh-sources must work before 020 ships.
- **Manifest-only list in `dist-templates`**: Rejected — framework manifest lists shipped scripts, not vault-local collectors.

## 3. Shim regeneration idempotency & user-customization detection

**Decision**:
- **Render**: Jinja2 `vault-script.sh.j2` with `vault_dir=resolve(vault)` and `spec` loaded from `research.spec.md` (same as `generator/scaffold._write_vault_script`).
- **Write**: Use `atomic_write.write_text(path=vault_dir / "vault", mode=0o755)`.
- **Idempotency**: Same inputs → byte-identical output (canonical `vault_dir` path, stable template version).
- **Customization heuristic** (for `--dry-run` warnings only; `--force` skips):
  - **Stock shim** if file contains the sentinel line `Generated by research-framework` (present in template header) AND SHA-256 matches last recorded hash in `_pipeline/shim-fingerprint.json` (new Phase 1 artifact, NOT `spec-fingerprint.json`).
  - **Customized** if sentinel absent OR hash differs from last framework-rendered hash stored in `shim-fingerprint.json`.
  - On successful regenerate, update `shim-fingerprint.json` with `{path, sha256, framework_version, rendered_at}`.

**Rationale**:
- Archaeology F2: broken shims lack correct `VAULT_DIR` but may still contain the sentinel — hash mismatch still allows safe `--force` repair.
- Avoids reintroducing blanket `is_user_owned_after_first_write: true` on `vault` (the trap that prevented auto-repair).
- `vault.local` override pattern deferred to Phase 2 (US4 / FR-007).

**Alternatives considered**:
- **Always overwrite without detection**: Rejected — operators who intentionally edited dispatch logic would lose work silently.
- **Diff against `dist-templates/scaffold-manifest.json` rendered_sha256**: Rejected for real vaults — manifest uses canonical fixture path hash, not operator's absolute `vault_dir` string embedded in shim.

## 4. Atomic-write contract (FR-018)

**Decision**: New module `pipeline/atomic_write.py` implementing:

```text
write_bytes(path, data) → temp in path.parent → flush+fsync file → os.replace → fsync directory (best-effort on platforms without directory fsync)
write_text(path, text, encoding=utf-8, mode=None)
write_json(path, obj, *, indent=2)
```

**Failure modes documented**:
| Failure | Behavior |
|---------|----------|
| Disk full during temp write | `OSError`; temp unlinked; destination unchanged |
| Process SIGKILL after temp complete, before `os.replace` | Orphan `*.tmp` in directory; readers see old file (safe) |
| SIGKILL after `os.replace` | Readers see new file or old file atomically — never torn content |
| Destination is directory | Fail fast with clear `IsADirectoryError` |
| Cross-filesystem path | `os.replace` may fail on some OS — require temp `dir=path.parent` |

**Rationale**: Consolidates 6+ ad-hoc `_atomic_write_*` helpers; verifier already uses `.tmp` + `rename` but not always parent-dir temp or fsync.

**Alternatives considered**:
- **Status quo (per-module helpers)**: Rejected — FR-018 requires positive test coverage and cycle JSON paths (`research.py` batch files) still use non-atomic `write_text`.

## 5. User-owned manifest semantics (FR-015) without the shim trap

**Decision**: Three-rule model:
1. **Manifest-listed path** → existing `scaffold_diff` matrix (`is_user_owned_after_first_write` flag).
2. **Path absent from manifest** → never touched by `compute_plan` / install overwrite (already true in `read_vault_baseline` docstring).
3. **`copy_scripts` on update/generate** → **merge mode**: copy framework-bundled script names from manifest entries under `scripts/` (if any); add missing framework files; **never delete** `scripts/collect_*.py` or other unlisted `.py` files.

Persist vault-side `_pipeline/scaffold-manifest-snapshot.json` on each successful `./vault update` apply — copy of dist manifest + `scripts/user_owned: [<relpath>]` discovered at update time (collectors auto-registered).

**Rationale**:
- Archaeology F6: collectors survived only because destructive copy never ran — `copy_scripts` currently `rmtree`s `scripts/` (generator/scripts.py:26-28).
- FR-015 positive guarantee requires fixing `copy_scripts`, not only manifest flags.
- Separates **framework scaffolding** (`vault` shim → FR-014) from **vault-local code** (`scripts/collect_*.py` → FR-015).

**Alternatives considered**:
- **Mark all `scripts/` user-owned in dist manifest**: Rejected — would prevent shipping updated `agent_call.py`, `vault_health.py`.
- **Blanket `is_user_owned_after_first_write: true` for shim**: Rejected — caused F2; replaced by FR-014 explicit verb.

## 7. `raw_data/` output layout for refresh-sources

**Decision**: Collectors write under `{vault}/raw_data/<source>/` per FR-013 spec text (not `_pipeline/raw/` from older TODO digest). Framework does not relocate collector output — only validates directory created/non-empty and reports paths in JSON summary.

**Rationale**: Spec FR-013 is authoritative; `vault_health._raw_data_mirror` already expects in-vault `raw_data/`.

**Alternatives considered**:
- **`_pipeline/raw/`**: Rejected — contradicts spec + health scanner.
