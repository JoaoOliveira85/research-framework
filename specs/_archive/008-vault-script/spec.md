# Spec 008 — Vault Unified Script

**Status:** shipped(2026-05-13, commit 86339fe) — **SHIPPED (early 0.2.x — pre-status-header-convention).** Shipped in the foundational autonomous-pipeline window (`feat(008): vault script template — ./vault entry point + systemd unit`, commit `86339fe`, pyproject `0.2.15`, 2026-05-13); the `./vault` shim is rendered from `templates/vault-script.sh.j2` today. Predates the CHANGELOG (which begins at 0.2.18) and the status-header convention.

## Problem Statement

A vault currently has no single entry point. Operating it requires knowing
which of `research-vault`, `python scripts/*.py`, or `.claude/commands/`
to call for a given task. This makes automation cumbersome:

- A `systemd` timer that runs research needs to know the venv path, the
  CLI invocation, and the spec file location.
- An iOS Shortcut that queries the vault has no stable command to call.
- A new user has no obvious starting point.

## Proposed Solution

A `vault` shell script at the vault root (`<vault>/vault`), generated at
scaffold time, that wraps all normal operations behind a stable sub-command
interface. Each vault has its own — no global installation, no multi-vault
conflicts.

```
./vault research          # run next research cycle(s)
./vault health            # deterministic health check (vault_health.py)
./vault audit             # full audit including Haiku checks (vault_audit.py)
./vault ask               # open interactive Claude Code session for Q&A
./vault generate "topic"  # non-interactive: produce a document file
./vault ingest <url|path> # add a source and optionally trigger a mini-cycle
./vault sources           # show source quality summary from sources.db
./vault sources lock <n>  # lock a source (prevent auto-archive)
./vault sources unlock <n># unlock a source
./vault sources reactivate <n> # re-activate an archived source
./vault report            # generate phase report
./vault coverage          # show coverage target status
./vault reindex           # rebuild _index.md, _concepts.md, _graph.md
./vault sync              # git add + commit + push vault notes
./vault maintain          # run full maintenance flow (health + fix + queue)
./vault help [cmd]        # usage for a sub-command
```

`vault ask` and `vault generate` are the two query modes:

- **`vault ask`** — opens an interactive Claude Code session (`claude` CLI)
  inside the vault directory. The user converses naturally; the `/ask`
  command and auto-escalation are available. Output stays in the terminal.
  For automation surfaces that can open a terminal (iOS Shortcuts via SSH,
  desktop launchers), this is the entry point.

- **`vault generate "topic"`** — runs non-interactively. Calls
  `scripts/generate_doc.py --topic "topic" --output _output/<slug>.md`.
  No terminal interaction expected; the output file is placed in `_output/`
  (gitignored by default, configurable). Suitable for cron jobs, Shortcuts
  that send a topic and consume a file, or agent pipelines.

## Non-Goals

- Replacing the `research-vault` Python CLI — `vault` is a thin shell
  wrapper that calls it (and standalone scripts) underneath
- A compiled binary or Python package — shell script is sufficient and
  keeps the vault self-contained; upgrade by regenerating or `./vault sync`
- Global `vault` command in `$PATH` — each vault has its own; users can
  symlink if they want a global alias

## Technical Design

### Generated from a template

`scaffold.py` renders `templates/vault-script.sh.j2` → `<vault>/vault`,
then `chmod +x` it. The template interpolates:
- `{{ vault_dir }}` — absolute path to the vault root (set at generation
  time; relative paths would break when called from another directory)
- `{{ spec.name }}` — for help text

### Script structure

```bash
#!/usr/bin/env bash
# vault — unified entry point for {{ spec.name }}
# Generated by research-vault at {{ timestamp }}. Re-generate with:
#   research-vault generate --spec <spec> --output . --dry-run
set -euo pipefail

VAULT_DIR="{{ vault_dir }}"
VENV_PYTHON="${VAULT_DIR}/.venv/bin/python"
SCRIPTS_DIR="${VAULT_DIR}/scripts"
RV="${VENV_PYTHON} -m research_vault.cli"

if [[ ! -f "${VENV_PYTHON}" ]]; then
    echo "ERROR: vault venv not found at ${VAULT_DIR}/.venv"
    echo "Run: cd ${VAULT_DIR} && python -m venv .venv && .venv/bin/pip install research-vault"
    exit 1
fi

CMD="${1:-help}"
shift || true

case "${CMD}" in
  research)
    exec "${RV}" generate --spec "${VAULT_DIR}/settings.yaml" --output "${VAULT_DIR}" --resume "$@"
    ;;
  health)
    exec "${VENV_PYTHON}" "${SCRIPTS_DIR}/vault_health.py" "${VAULT_DIR}" "$@"
    ;;
  audit)
    exec "${VENV_PYTHON}" "${SCRIPTS_DIR}/vault_audit.py" "${VAULT_DIR}" --full "$@"
    ;;
  ask)
    # Open interactive Claude Code session inside the vault.
    # The user can then run /ask naturally; auto-escalation is wired.
    cd "${VAULT_DIR}"
    exec claude "$@"
    ;;
  generate)
    # Non-interactive document generation — outputs a file.
    exec "${VENV_PYTHON}" "${SCRIPTS_DIR}/generate_doc.py" \
        --vault "${VAULT_DIR}" --topic "$*" \
        --output "${VAULT_DIR}/_output"
    ;;
  ingest)
    exec "${VENV_PYTHON}" "${SCRIPTS_DIR}/ingest.py" "${VAULT_DIR}" "$@"
    ;;
  sources)
    exec "${RV}" sources --vault "${VAULT_DIR}" "$@"
    ;;
  report)
    exec "${RV}" report --vault "${VAULT_DIR}" "$@"
    ;;
  coverage)
    exec "${RV}" coverage --vault "${VAULT_DIR}" "$@"
    ;;
  reindex)
    exec "${RV}" reindex --vault "${VAULT_DIR}" "$@"
    ;;
  sync)
    cd "${VAULT_DIR}"
    git add data_vault/ _pipeline/
    git commit -m "vault sync $(date +%Y-%m-%d)" || echo "[sync] nothing to commit"
    git push
    ;;
  maintain)
    exec "${VENV_PYTHON}" "${SCRIPTS_DIR}/vault_maintain.py" "${VAULT_DIR}" "$@"
    ;;
  help|--help|-h)
    echo "Usage: ./vault <command> [args]"
    echo ""
    echo "Commands:"
    echo "  research   Run next research cycle(s)"
    echo "  health     Deterministic vault health check"
    echo "  audit      Full audit with Haiku quality checks"
    echo "  ask        Open interactive chat session (Claude Code)"
    echo "  generate   Non-interactive document generation (outputs a file)"
    echo "  ingest     Add a source (optionally trigger a mini-cycle)"
    echo "  sources    Manage source quality DB"
    echo "  report     Generate phase report"
    echo "  coverage   Show coverage target status"
    echo "  reindex    Rebuild vault index files"
    echo "  sync       Commit and push vault notes to git"
    echo "  maintain   Run full maintenance flow"
    ;;
  *)
    echo "Unknown command: ${CMD}"
    echo "Run './vault help' for usage."
    exit 1
    ;;
esac
```

Note: `vault audit` and `vault maintain` depend on specs 006 and 010
respectively. The script stubs them at generation time; they become
functional once those specs ship.

### Stubs for unimplemented sub-commands

Commands whose backing scripts don't exist yet print a helpful error:

```bash
# In vault_audit.py stub until spec 006 ships:
echo "vault audit requires spec 006 (Vault Audit) to be implemented."
echo "Run './vault health' for the deterministic check."
exit 1
```

### systemd timer example (generated into `_pipeline/systemd/`)

`scaffold.py` writes an example unit file to help users set up scheduled
research:

```ini
# _pipeline/systemd/vault-research.service
[Unit]
Description={{ spec.name }} — research cycle
After=network.target

[Service]
Type=oneshot
ExecStart={{ vault_dir }}/vault research
WorkingDirectory={{ vault_dir }}
StandardOutput=append:{{ vault_dir }}/_pipeline/research.log
StandardError=append:{{ vault_dir }}/_pipeline/research.log

[Install]
WantedBy=default.target
```

Users install it with `systemctl --user enable` after copying to
`~/.config/systemd/user/`.

## Acceptance Criteria

1. After `scaffold.py`, `<vault>/vault` exists, is executable, and
   `./vault help` prints usage without error
2. `./vault health` calls `vault_health.py` with the correct vault path
3. `./vault coverage` calls `research-vault coverage --vault <vault>`
4. `./vault research` calls the orchestrator in resume mode
5. `./vault ask` changes into the vault directory and launches `claude` CLI
6. `./vault generate "topic"` calls `scripts/generate_doc.py` and places
   the output in `<vault>/_output/`
7. Unknown sub-commands exit 1 with a helpful message
8. The venv-missing guard prints a clear error and exits 1
9. `_pipeline/systemd/vault-research.service` is written with the correct
   vault path and spec name interpolated
10. All scaffold tests pass; new test asserts `vault` file exists and is executable

## Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Hardcoded vault path breaks after move | Medium | Medium | Document re-generation; `VAULT_DIR` is clearly labelled as generated |
| `vault ask` requires `claude` CLI which may not exist | Medium | Low | Command exits with a clear error and install hint if `claude` not found |
| `vault generate` requires a new `scripts/generate_doc.py` (spec 008 dependency) | Medium | Low | Script stubs out with a helpful error until implemented |
| Script accumulates debt as sub-commands grow | Low | Low | Template is the source; regenerate to get updates |
